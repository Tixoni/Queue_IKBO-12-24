# Бот очереди к практическим работам

Python 3.11+, aiogram 3, PostgreSQL (asyncpg). Бот работает через long polling. Транзакции и уникальность `(очередь, Telegram user_id)` в PostgreSQL предотвращают дубли и гонки между одновременными нажатиями.

## Запуск

1. Установите Python 3.11+.
2. В отдельном PowerShell: `py -m venv .venv`, затем `.venv\Scripts\Activate.ps1`.
3. `pip install -r requirements.txt`.
4. Создайте `secrets/.env` по образцу в `secrets/README.md` (нужны `BOT_TOKEN` и `DATABASE_URL`).
5. Запустите бота командой `py main.py`.

Секреты (токен Telegram и список ID администраторов) хранятся в `secrets/.env`, папка исключена из Git. Расписание берётся из файла в репозитории (см. ниже), запись открыта на 14 дней вперёд.

При сетевой ошибке `api.telegram.org` проверьте доступ Telegram Bot API из вашей сети; бот автоматически повторяет попытки подключения.

## Запуск в Docker (бот + PostgreSQL)

Нужны Docker и Docker Compose. В `secrets/.env` (образец — `.env.example`) задайте `BOT_TOKEN`, `ADMIN_IDS` и пароль базы `POSTGRES_PASSWORD` — только латиница и цифры, он подставляется в строку подключения. `DATABASE_URL` для Docker не нужен: compose собирает его сам.

```
docker compose --env-file secrets/.env up -d --build
docker compose logs -f bot
```

PostgreSQL наружу не открыт: в `docker-compose.yml` у него нет `ports`, он подключён только к внутренней сети `internal` (без выхода в интернет), и до него достаёт только бот по имени `db`. Поэтому на сервере не занимается порт 5432 и не будет конфликта с другим PostgreSQL. Проверка: `docker compose ps` — в колонке PORTS у `db` пусто, только `5432/tcp`, без `0.0.0.0:`.

Данные лежат в томе `pgdata` и переживают `docker compose down` и пересборку (удаляет их только `docker compose down -v`).

**Перенос базы со старого хостинга.** Сделайте дамп старой базы (`pg_dump --format=custom --no-owner --no-privileges --file=queue.dump "<строка подключения>"`), затем на новом сервере:

```
docker compose --env-file secrets/.env up -d --wait db
docker compose --env-file secrets/.env exec -T db pg_restore -U queue -d queue --no-owner --no-privileges < queue.dump
docker compose --env-file secrets/.env up -d --build bot
```

Бот запускается после восстановления, чтобы он не успел создать пустые таблицы. Файл дампа содержит данные студентов — удалите его после переноса.

**Бэкап:** `docker compose --env-file secrets/.env exec -T db pg_dump -U queue -d queue --format=custom > backup.dump`.

## Структура кода

- `main.py` — сборка: БД, клиент расписания, диспетчер, polling.
- `src/bot/handlers.py` — обработчики команд, кнопок и диалогов (aiogram `Router`).
- `src/bot/screens.py` — сборка текста и клавиатуры экранов.
- `src/bot/keyboards.py`, `src/bot/formatting.py` — клавиатуры и форматирование (`Lesson` — разобранная пара).
- `src/sync.py` — раскладывает расписание на ближайшие 14 дней (при старте и каждые 6 часов).
- `src/db.py` — PostgreSQL: схема создаётся автоматически при старте, `src/schedule.py` — разбор iCalendar МИРЭА; `schedule/` — файл расписания, `tools/update_schedule.py` — его обновление.

## Тесты

```
pip install -r requirements-dev.txt
docker run -d --name queue-test-pg -e POSTGRES_PASSWORD=test -p 5433:5432 postgres:16
TEST_DATABASE_URL=postgresql://postgres:test@localhost:5433/postgres pytest
```

Тесты базы работают с настоящим PostgreSQL из `TEST_DATABASE_URL`: каждый тест создаёт свою временную схему и удаляет её (без переменной эти тесты пропускаются). Остальные тесты используют фейковые объекты Telegram — реальный токен и сеть не нужны. В GitHub Actions тесты гоняются на каждый push.

## Возможности

- Постоянная панель внизу экрана: «📝 Записаться», «👥 Мои записи», «📌 Темы», «👤 Имя» (появляется после /start). Главное меню в сообщении дублирует её и для админов содержит «Администрирование».
- Запись начинается с актуального расписания: выбор дня → пара с временем, преподавателем и аудиторией → открытая очередь.
- Карточка своей записи показывает соответствующую пару из расписания.
- Очередь автоматически создаётся для пары из расписания и доступна без ручного разрешения.
- Раздел «📌 Темы» отдельно от очередей: списки занятых тем ведутся по предметам и живут весь семестр. Любой участник может создать список, а занять в нём — одну тему; рядом с темой показывается имя. Админ правит название списка и темы («⚙️ Редактировать») и может заполнить список из Google Таблицы командой `/import_topics ID_списка ссылка` (столбцы: ФИО, тема). Из карточки очереди есть переход «📌 Темы по предмету».
- Админ может переименовать очередь кнопкой «✏️ Изменить название» в её карточке — например, дописать условие сдачи.
- Запись в очередь и выход из неё без ручного ввода ID.
- Администраторская команда `/admin_add_user ID_очереди TELEGRAM_ID Имя` позволяет вручную добавить студента.
- Команда `/queue` показывает ваши записи.

Очередь использует Telegram-имя, пока пользователь не задаст отображаемое имя кнопкой «Указать имя».

При первом открытии пары бот создаёт для неё постоянную очередь. ID очереди показывается администраторам для ручного добавления студентов.

Расписание лежит в репозитории файлом `schedule/IKBO-12-24.ics` (выгрузка iCalendar с `schedule-of.mirea.ru`), бот читает его без сети: сайт университета отвечает только из части российских сетей, и с зарубежного хостинга до него не достучаться. Пары повторяются раз в две недели, исключения и конец семестра берутся из самого файла. Если расписание поменялось или начался новый семестр, на своём ПК выполните `python tools/update_schedule.py`, закоммитьте обновлённый файл и запушьте — бот подхватит его после деплоя.
